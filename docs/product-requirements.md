# Chrome AI Agent 插件 MVP 产品需求文档

## 1. 产品概述

### 1.1 产品定位

本产品是一款面向 Chrome 浏览器的通用网页 AI Agent 插件。插件通过读取当前网页的可见上下文，理解用户目标，调用自建后端代理聚合的主流 AI 模型能力，生成可解释的操作计划，并在用户确认后执行低风险网页动作。

首版产品不追求完全自动化，而是采用“计划先行、确认后执行”的协作式 Agent 模式：AI 负责理解页面、拆解任务、推荐动作；用户负责确认关键步骤；插件负责在浏览器中执行受控动作。

### 1.2 目标用户

- 经常在网页中阅读、检索、整理信息的个人用户。
- 需要在表单、后台系统、资料页面中重复操作的知识工作者。
- 希望使用多个 AI 模型能力，但不想在多个产品之间切换的高级用户。
- 后续可扩展到企业团队，用于统一模型接入、权限控制、审计和成本管理。

### 1.3 产品目标

- 在任意通用网页中提供上下文感知的 AI Agent 入口。
- 支持页面总结、内容问答、信息提取、表单辅助填写和低风险页面操作。
- 通过自建后端代理统一接入 OpenAI、Anthropic、Gemini、DeepSeek、Qwen/DashScope 等模型能力。
- 建立安全、可审计、可控的浏览器执行机制，避免模型直接操作页面或执行任意脚本。
- 为后续自动化任务、企业版策略和模型路由打下基础。

### 1.4 非目标范围

MVP 阶段不包含以下能力：

- 不针对智慧树或其他单一站点做定制流程。
- 不支持全自动连续执行任务。
- 不自动提交支付、购买、登录、删除、发帖、转账等高风险动作。
- 不在插件前端保存第三方模型 API Key。
- 不上传 Cookie、localStorage、密码、隐藏字段、支付信息或浏览器完整历史。
- 不实现完整企业租户、团队成员管理、发票、复杂计费等商业化后台。

## 2. 核心场景

### 2.1 网页总结与问答

用户打开任意资讯、博客、文档或知识库页面后，可以在插件侧边栏中输入问题，例如“总结这篇文章的关键观点”或“把这一页整理成待办清单”。插件提取当前页面的可见文本摘要和结构化元素清单，提交给后端 Agent，由模型返回总结、答案或后续建议。

成功标准：

- 用户无需复制粘贴网页正文。
- 插件明确展示使用的是当前页面上下文。
- 页面内容过长时，前端或后端可进行摘要压缩。

### 2.2 信息提取

用户可以要求 Agent 从页面中提取结构化信息，例如表格、价格、联系人、链接、时间线、产品参数等。插件优先通过 DOM 结构识别页面中的列表、表格和可点击元素，再由模型进行字段归纳。

成功标准：

- 结果以结构化格式展示，例如表格或 JSON 预览。
- 支持用户复制结果。
- 页面没有可提取内容时，给出明确提示。

### 2.3 表单辅助填写

用户在网页表单中输入目标，例如“帮我根据这段信息填写表单”。Agent 先识别页面中的可填写字段和标签，生成填写计划，并展示每个字段的拟填写内容。用户确认后，插件将内容写入对应输入框。

成功标准：

- 所有写入动作必须先展示计划。
- 密码、验证码、支付卡号、身份证等敏感字段默认不填写。
- 执行完成后展示成功字段、跳过字段和失败原因。

### 2.4 低风险页面操作

用户可以要求 Agent 执行低风险页面动作，例如展开更多内容、点击筛选项、勾选普通选项、跳转到详情页、复制页面信息。Agent 生成操作计划并请求用户确认，确认后由 Content Script 执行受控动作。

成功标准：

- 每一步动作都能对应到可解释的页面元素。
- 页面元素变化或无法定位时停止执行并提示用户。
- 高风险动作被拦截或要求二次确认。

## 3. MVP 功能需求

### 3.0 当前实现状态

当前仓库已经落地一个本地演示版 MVP：Side Panel 使用聊天流承载任务输入、计划、回答、动作确认和执行结果；本地 Node 代理通过 OpenAI 兼容 Chat Completions 接口生成回答和工具动作；本地认证、任务历史、额度扣减和多供应商模型选择已具备基础实现。审计、成本统计、自动降级和企业级策略仍是后续产品化范围。

当前已实现能力：

- 页面上下文采集、选中文本快捷菜单和活动标签页刷新。
- 聊天式任务输入、流式回答、计划展示、思考块折叠。
- `open_url` 浏览器级工具确认执行，以及 Content Script 白名单动作执行框架。
- 本地代理 `/api/agent/runs`、`/api/agent/runs/:runId/stream`、`/api/agent/runs/:runId/stop`。

当前未实现或仅为占位：

- 真实登录、用户额度、任务历史和审计日志。
- 多供应商模型路由、降级和数据库持久化。
- 企业租户、管理后台和商业化计费。

### 3.1 插件入口与主界面

插件首版采用 Chrome Side Panel 作为主要交互入口，提供以下区域：

- 当前页面状态：展示页面标题、域名、是否已读取页面上下文。
- 任务输入框：用户输入自然语言目标。
- 模型状态：展示默认模型路由、可用模型能力和后端连接状态。
- Agent 运行区：展示推理状态、计划、待确认动作、执行结果和错误信息。
- 历史区：展示当前用户近期任务，可查看详情或删除。

### 3.2 登录与账号

首版要求用户登录后使用。账号体系用于保护后端模型代理、控制成本、记录审计日志和支持后续商业化。

功能要求：

- 支持邮箱和验证码登录，或预留第三方登录扩展。
- 登录态存储在插件安全可用的本地存储中，不保存模型供应商 Key。
- 后端返回用户额度、可用模型、调用限制和基础账户信息。
- 用户退出登录后清除本地会话信息。

### 3.3 页面上下文采集

插件仅在用户打开侧边栏并主动发起任务时读取当前标签页内容。

默认采集范围：

- 当前页面 URL、标题、域名。
- 用户选中的文本。
- 页面可见文本摘要。
- 可交互元素清单，例如按钮、链接、输入框、下拉框、复选框。
- 表格、列表、标题层级等结构化信息。

禁止采集范围：

- 密码字段内容。
- 支付卡号、验证码、身份证等敏感字段内容。
- Cookie、localStorage、sessionStorage。
- 隐藏字段、不可见 DOM 文本。
- 浏览器历史记录、其他标签页内容。

### 3.4 Agent 计划生成

用户提交任务后，后端 Agent 需要返回可解释的计划。计划至少包含：

- 任务理解：Agent 对用户目标的简短复述。
- 所需上下文：说明是否需要读取页面、选区或用户补充信息。
- 动作列表：每一步动作的工具名称、目标元素、预期效果和风险级别。
- 用户确认点：哪些动作需要确认，哪些动作被禁止执行。

计划状态：

- `draft`：Agent 正在生成计划。
- `requires_confirmation`：等待用户确认。
- `running`：确认后正在执行。
- `completed`：执行完成。
- `blocked`：因权限、安全策略或页面变化停止。
- `failed`：模型、网络或执行层错误。

### 3.5 受控动作协议

模型不得直接执行浏览器脚本，也不得返回任意 JavaScript 交给插件执行。所有页面动作必须映射到前端白名单工具。

MVP 支持的工具：

| 工具                  | 说明                                           | 风险级别 |
| --------------------- | ---------------------------------------------- | -------- |
| `read_page`           | 读取当前页面可见摘要和结构化元素               | 低       |
| `summarize_selection` | 总结用户选中文本                               | 低       |
| `extract_table`       | 提取页面表格或列表                             | 低       |
| `highlight_element`   | 高亮页面元素，帮助用户确认                     | 低       |
| `click_element`       | 点击普通按钮、链接或选项                       | 中       |
| `fill_input`          | 填写普通输入框                                 | 中       |
| `scroll_page`         | 页面滚动或跳转到元素位置                       | 低       |
| `open_url`            | 打开新的浏览器标签页并访问指定 http/https 网址 | 中       |
| `copy_result`         | 将 Agent 结果复制到剪贴板                      | 低       |

MVP 禁止或默认拦截的动作：

- 提交付款、购买、转账、提现。
- 登录、注册、修改密码、提交验证码。
- 发布公开内容、发送私信、发送邮件。
- 删除、清空、批量修改数据。
- 下载未知文件或上传本地文件。
- 执行任意脚本或读取浏览器敏感数据。

### 3.6 用户确认机制

所有中风险动作必须展示确认卡片。确认卡片包含：

- 动作名称。
- 目标页面元素描述。
- 将要填写或点击的内容。
- 风险提示。
- “执行”“跳过”“拒绝并反馈”操作。

高风险动作默认不执行。若后续版本允许部分高风险动作，必须增加二次确认、审计日志和站点级策略。

### 3.7 任务历史与审计

后端保存任务历史和动作审计，用于用户回看、问题排查和成本统计。

记录内容：

- 用户 ID。
- 任务 ID。
- 页面域名和 URL。
- 用户目标。
- 模型路由结果。
- 动作计划和确认结果。
- 执行状态、错误原因和耗时。
- Token 或调用成本统计。

隐私要求：

- 任务历史支持用户删除。
- 敏感字段不进入日志。
- 管理后台仅可查看必要审计信息，不展示用户隐私正文，除非用户主动提交反馈。

## 4. 技术架构

### 4.1 前端技术栈

- Vue 3：插件侧边栏 UI 和状态管理。
- Vite：开发与构建。
- pnpm：包管理。
- TypeScript：推荐使用，降低插件消息协议和动作协议的维护成本。
- Chrome Manifest V3：插件标准。

### 4.2 插件模块

| 模块           | 职责                                                   |
| -------------- | ------------------------------------------------------ |
| Side Panel     | 主交互界面，负责输入任务、展示计划、确认动作、查看结果 |
| Content Script | 读取当前页面可见上下文，执行白名单 DOM 动作            |
| Service Worker | 管理插件生命周期、消息转发、权限请求和后端通信         |
| Options Page   | 后续用于账号设置、模型偏好、隐私设置                   |
| Shared Types   | 定义页面上下文、Agent 计划、工具动作、后端响应类型     |

### 4.3 后端代理

后端负责统一封装模型供应商，前端不直接调用第三方模型 API。

核心职责：

- 用户认证和会话校验。
- 模型供应商 Key 托管。
- 模型路由和降级。
- Agent 计划生成。
- 动作安全校验。
- SSE 推送运行状态。
- 调用日志、成本统计和限流。

首版模型接入：

- OpenAI：文本推理、工具调用、结构化输出。
- Anthropic Claude：长上下文理解、工具调用、计算机使用能力参考。
- Google Gemini：多模态和函数调用扩展。
- DeepSeek：高性价比推理和工具调用。
- Qwen/DashScope：中文场景、国内可用性和工具调用。
- xAI/Grok：预留供应商扩展位。

## 5. 接口草案

本节包含两类接口：当前本地演示版已实现的 Agent run 接口，以及后续产品化需要补齐的认证、模型列表、动作确认和历史接口。

### 5.0 当前本地接口

当前仓库已实现：

```http
GET /health
GET /health/openai
POST /api/agent/runs
POST /api/agent/runs/:runId/stream
POST /api/agent/runs/:runId/stop
```

动作确认当前发生在插件内：Side Panel 在聊天消息中展示 `执行` / `跳过`，确认后通过 Service Worker 转发给 Content Script 或 Background 执行。

- `action_request`：需要用户确认的动作。

## 6. 权限与安全

### 6.1 Chrome 权限原则

MVP 遵循最小权限原则：

- 仅在用户触发插件时读取当前标签页。
- 对敏感 host 权限按需申请。
- 不使用远程托管代码。
- 不绕过网页自身权限控制。
- 不读取其他标签页内容。

建议权限：

- `sidePanel`：提供侧边栏交互。
- `activeTab`：用户触发后访问当前标签页。
- `storage`：保存登录态、设置和少量本地状态。
- `scripting`：按需注入 Content Script 或执行受控脚本。

### 6.2 安全策略

- 后端必须校验所有模型返回动作，只允许白名单工具。
- 前端执行动作前再次校验工具名称、元素 ID 和风险级别。
- Content Script 不接受任意 JavaScript 字符串。
- 对页面元素建立短期映射 ID，避免后端直接持有 DOM 引用。
- 页面结构变化后，动作必须重新确认。
- 用户可随时停止当前 Agent 任务。

### 6.3 风险分级

| 风险级别 | 定义                               | 处理方式           |
| -------- | ---------------------------------- | ------------------ |
| 低       | 读取、总结、滚动、高亮、复制结果   | 可直接执行或轻提示 |
| 中       | 点击普通按钮、填写普通输入框       | 必须用户确认       |
| 高       | 支付、登录、提交、删除、发布、上传 | MVP 默认禁止       |

## 7. 交互流程

### 7.1 首次使用

1. 用户安装插件。
2. 用户点击插件图标打开 Side Panel。
3. 插件提示登录。
4. 用户完成登录后，插件展示当前页面状态和任务输入框。
5. 用户输入目标并发起任务。

### 7.2 常规 Agent 任务

1. 用户在当前网页打开插件侧边栏。
2. 用户输入自然语言目标。
3. 插件采集当前页面允许范围内的上下文。
4. Service Worker 将任务提交到后端。
5. 后端 Agent 生成计划并通过 SSE 返回。
6. 插件展示计划和待确认动作。
7. 用户确认、跳过或拒绝动作。
8. Content Script 执行确认后的受控动作。
9. 插件展示执行结果和后续建议。

### 7.3 异常流程

- 未登录：提示登录后继续。
- 页面不可访问：说明当前页面受浏览器限制，例如 Chrome Web Store、浏览器内置页面。
- 后端不可用：提示稍后重试，并保留用户输入。
- 模型失败：后端尝试降级模型；降级失败后返回可理解错误。
- 元素失效：停止执行，提示页面已变化，需要重新生成计划。
- 权限不足：提示用户授权当前站点权限。

## 8. 验收标准

### 8.1 产品验收

- 用户可以在任意普通网页打开 Side Panel 并发起 Agent 任务。
- 插件可以总结当前页面内容，并回答基于页面的问题。
- 插件可以识别表单字段，生成填写计划，用户确认后写入普通输入框。
- 插件可以识别高风险动作，并拒绝自动执行。
- 用户可以查看任务结果、停止任务、删除任务历史。

### 8.2 权限验收

- 未经用户触发，插件不读取当前页面内容。
- 插件不读取其他标签页内容。
- 插件不上传密码字段、Cookie、localStorage 或隐藏字段。
- Manifest V3 构建产物中不包含远程托管代码。
- 敏感站点权限使用按需授权策略。

### 8.3 Agent 可靠性验收

- 模型返回未知工具名时，后端拒绝执行。
- 模型请求高风险动作时，后端标记为 `blocked`。
- 页面元素定位失败时，插件停止动作并提示用户。
- SSE 中断时，前端展示重连或重试入口。
- 后端模型调用失败时，支持降级或返回明确错误。

### 8.4 安全验收

- 所有执行动作均有审计日志。
- 用户确认记录可追溯。
- 用户可以删除自己的任务历史。
- 第三方模型 Key 只保存在后端安全配置中。
- 前端不执行模型生成的任意脚本。
